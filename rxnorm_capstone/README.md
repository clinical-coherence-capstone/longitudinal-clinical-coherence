# RxNorm medication-identity component (capstone: Longitudinal Clinical Coherence)

Generated by `scripts/render_docs.py` from `data/*.csv` and `reports/validation_report.json`. Do not edit numbers by hand;
re-run the pipeline (see *How to regenerate*).

**Evidence labels used throughout:** `[SOURCE]` = read from the uploaded archive by the script; `[EXTERNAL]` = stated in NLM
documentation (URLs in `SOURCE_AND_LICENSE.md`, kept separate from archive evidence); `[INFERENCE]` = derived by this project;
`[ASSUMPTION]` = adopted without verification.

## 1. Purpose and boundaries

Supports **medication-identity and evidence-attribution tests** for the verifier: can the terminology tell an ingredient from
a specific product, a single agent from a combination, one strength/dose form/salt from another, one medication from a
different one, and a resolvable input from an underspecified one.

**RxNorm validates terminology identity only.** Nothing here shows a treatment recommendation is clinically correct or safe,
and RxNorm alone cannot detect a longitudinal coherence failure (that needs conversation state, evidence provenance and the
verifier logic). The DailyMed linkage is **not done** (see section 9).

## 3. Scope decision

* **What a row is.** `concepts.csv`: one row per unique RxNorm concept (RXCUI). `input_aliases.csv`: one row per *input string*
  (many inputs can point to one RXCUI; one input could point to many). Test cases are **not** in this resource; they will be
  built by the team from concept pairs (`data/contrast_checks_results.csv` lists the pairs this resource supports).
* **Counts.** 29 unique concepts; 41 input rows
  (40 unique after casefold/whitespace normalization: `Metformin` and `metformin` collapse);
  21 relationship-derived contrast checks.
* **Is ~20-30 concepts appropriate?** `[INFERENCE]` For a *starter terminology resource that demonstrates each identity contrast
  with real, verified examples*, yes: the 29 concepts fell out of the coverage plan
  (4 seed ingredients plus the minimum partners and variants needed per contrast), not from hitting a number. It is **not** a
  statistically justified evaluation sample size, is not comprehensive, and covers 3 drug families plus 2 partner ingredients.
  Before any stronger claim, the team needs: more drug families (including look-alike/sound-alike pairs from an
  external safety list), more strengths and dose forms per family, pack concepts (GPCK/BPCK, not included), and
  a conversation-level test set with its own sample-size analysis.

IN/PIN/MIN/BN because those term types carry no strength or dose form.

## 5. Term types and what each can and cannot express

Term types `[EXTERNAL]` (Appendix 5): IN ingredient; PIN precise ingredient (salt/isomer form); MIN multiple ingredients;
BN brand name; SCD ingredient+strength+dose form (generic); SBD the same with brand. Packs, forms, groups and components
exist in the release but are only used as relationship neighbours here.

| Distinction | RxNorm can represent | Needs something else |
|---|---|---|
| Ingredient vs product | Separate concepts (IN vs SCD/SBD) linked by `ingredient_of`/`has_ingredient` chains | Which one a speaker meant |
| Single vs combination | MIN concept plus per-product ingredient set | Whether evidence about a component applies to the combination |
| Strengths / dose forms / salts | Distinct SCD (and PIN) concepts | Clinical interchangeability, titration |
| Different medication | Disjoint ingredient sets | Turn structure, who said what, attribution logic |
| Ambiguous/incomplete mention | Nothing: RxNorm holds names, not mentions | A linker with context; here only exact string matching is tested |

## 6. Relationship semantics (verified)

`[EXTERNAL]` RXNREL's `REL`/`RELA` state the relationship **of the second concept (RXCUI2) to the first (RXCUI1)**.
`[SOURCE]` Checked against the whole subset: for 361048/361048 CUI-level rows of the exported relationship types, the
(TTY of RXCUI2, RELA, TTY of RXCUI1) combination matches the NLM Appendix 1 table (PASS). Example:
row `RXCUI1=IN, RELA=has_ingredient, RXCUI2=SCDC` means *the SCDC has_ingredient the IN*. Thus in `relationships.csv`,
`subject_rxcui` = RXCUI2, `object_rxcui` = RXCUI1, and `raw_rxcui1/raw_rxcui2` preserve the source order.
Relationships are **not symmetric**: each direction is a separate row with its own RUI and (usually) a different RELA
(`has_ingredient`/`ingredient_of`, `tradename_of`/`has_tradename`, ...). 368 rows exported;
every row has its inverse in the set (PASS) and a documented TTY pair (PASS).
Ingredient links are walked as: SCD/SBD `consists_of` SCDC, SCDC `has_ingredient` IN and/or `has_precise_ingredient` PIN,
PIN `form_of` IN; MIN `has_part` IN/PIN; BN `tradename_of` IN. Where both a MIN path and an SCDC path exist they must agree
(PASS).

## 8. How to regenerate

```bash
cd rxnorm_capstone
python3 scripts/build_rxnorm_component.py --zip /path/to/RxNorm_full_prescribe_10052026.zip --config-dir config --out-dir .
python3 scripts/render_docs.py --out-dir .
```
Python 3.8+ standard library only (no `requirements.txt` needed). The script streams the RRF files from the ZIP read-only and
records its SHA-256 before and after. Exit code 2 = a critical check failed; an unresolved seed fails the run unless
`--allow-unresolved` is passed (it is still reported). Rerunning on the same ZIP gives byte-identical CSVs
(verified; only `generated_utc` in the report changes). To add concepts, edit `config/seed_concepts.csv` (exact RxNorm
name + expected TTY; the script never substitutes a different concept) and `config/contrast_checks.csv`.

## 10. Limitations

1. Current Prescribable Content only: approximates currently marketed US prescription drugs; retired/obsolete concepts and
   all history are absent, so this release cannot show how an RXCUI changed over time.
2. No semantic type (STY): `concept_type` is derived from TTY; STY is NOT VERIFIED (not in the archive).
3. Release-notes counts and an official checksum for this exact 10/05/2026 file were not retrieved: NOT VERIFIED (X1, X2).
4. Pinned RXCUIs in `config` were taken from this same release: they detect drift on a future release, they are not independent confirmation.
5. Exact string matching is order- and wording-sensitive; real linking needs ingredient-set matching (use `ingredient_rxcuis`).
6. Three drug families, no packs, no non-oral forms, no vaccines/biologics: not comprehensive.
7. Names reflect the US-centric RxNorm model; "branded" means a RxNorm brand-name concept, not label equivalence.
